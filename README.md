# もしもトーク

個別避難計画を、書く前に話す道具です。**同じことを二度聞かない。空いた時間で、もしもの話をする。**

- **誰の：** 個別避難計画を作るために訪問する人と、何度も同じことを聞かれるご本人。今回はケアマネジャーに絞って作りました
- **どんな困りごとを：** 使いたい情報はケアプランにもう入っているのに、様式が違うので、ご本人はまた同じことを答えています
- **どう解くか：** ケアプランと個別避難計画書をつなぎ、分かっていることは聞かず、まだ決まっていないことだけを話します。話したことは、その場で計画の欄に入ります

Built with Claude: Japan 2026 の期間中（2026-11-02〜）に開発しています。リポジトリの名前 `hinan-hanashi` は、開発中の呼び名のままです。

## 公開版で試す
https://built-with-claude-japan-2026-jingushi.onrender.com

- **合言葉が必要です。** 審査員の方には、提出フォームでお伝えします。ブラウザが聞いてくる利用者名は何でもかまいません。パスワードの欄に合言葉を入れてください
- **本物の Claude で動きます。** このリポジトリと同じコードです。答えは毎回少し変わります
- **デモ動画は、答えを固定して録画しました。** 撮り直しても同じ画面になるようにするためです。動画の左上に「画面は仮の答え」と出るのは、このためです。動画の答えと公開版の答えは、同じとは限りません
- **すぐ試すには：** 最初の画面で「ケアマネジャー」を選び、「台本つきで試す」の「岡野さん」を押します。話の画面で「台本の次の声メモを入れる」を押すたびに、本物の Claude が計画の欄へ書き込みます
- 入れるのは架空のデータだけにしてください。パソコンの Chrome か Edge で開いてください

### 見たことのない CSV で試す
見本を読んでいるだけではないことは、自分で作った CSV で確かめられます。お使いの AI に次の文を渡して、できた中身を `.csv` のファイルに保存し、最初の画面で「ケアマネジャー」を選んでから、「ケアプラン」の枠へドラッグして「つないで進む」を押してください。

```text
介護ソフトが書き出すケアプランの CSV を作ってください。
人物、住所、電話番号はすべて架空にし、電話番号は 000 から始めてください。実在の人や地名は使わないでください。
列の名前と順番は、あなたが考えた架空のソフトらしいものにしてください。
入れる内容：氏名、生年月日、住所、電話、要介護度、緊急連絡先、同居家族、週間のサービス予定（「月水金 デイサービス 9:00-16:00」の1件だけ）、歩き方、階段の上り下り、寝室の場所、家のまわりの危険な所
1行目は見出し、2行目に1人分を入れてください。値の中にカンマは入れないでください。CSV の中身だけを出してください。
```

読み解き役が見出しを読んで列をつなぎます。列の値は記号に置き換えて送るので、送る前に画面で確かめられます。この CSV には台本がないので、話の画面では声メモを話すか、文字で打って「計画に入れる」を押してください。

## なぜ作ったか
個別避難計画は、災害のとき一人で避難するのが難しい人について、誰と、何で、どこへ、何分で避難するかを前もって決めておく計画です。作った人が住む奄美市の名瀬地区では、2025年6月の市議会答弁で作成済みが約1割でした（奄美市全体は 2026-04-01 時点で 30.6%）。

最初は入力ツールを作るつもりでした。考えが変わったきっかけは2つです。

- **書く前の段階で止まっている：** 国の調査（2026-04-01）を集計すると、計画がない約568万人のうち同意済みは約23万人（4%）で、約546万人は同意の手前にいます。内訳は分かりません。内閣府の「個別避難計画に取り組むみなさまへ」追補版（2025年6月）は、計画づくりが地域のつながりの再構築につながるとしています。足りないのは入力より、話すことかもしれないと考えました
- **情報はもうある：** 個別避難計画で使いたい情報は、ケアプランのアセスメント、避難行動要支援者名簿、救急医療情報キットなどに、様式を変えて入っています。それでも、計画を作るときにご本人は同じことを答えています

そこで、2つのデータをつなぎ、分かっていることは聞かず、必要なことだけを話す道具に変えました。

## 現場で聞いたこと
作った人が、市の担当の方とケアマネジャーの方に直接聞いた話です（2026-11-03〜05）。

- **誰が作るかが決まりきっていない：** ケアマネジャーか、民生委員か、自治会長か。施設に入っている方はケアマネジャーへ、そのほかの方は自治会長へ、計画が必要な方の名簿が渡されているとのことでした
- **紙で出して、市の職員が打ち直している：** 名簿をもとに聞き取り、紙で提出し、市の職員がソフトに打ち込みます。ソフトは CSV の取り込みもできると聞きました
- **ケアマネジャーに、作る時間がない：** ケアプランのアセスメントの量が大きく増え、個別避難計画に割く時間が作れないという声でした。以前はよく話に出たものの、この1年以上は作るように言われていない、とも聞きました

聞いて分かったのは、同じことを聞き直す手間と、紙から打ち直す手間が、実際にあることです。この道具は、増えたアセスメントの情報をそのまま使い、CSV で市に渡すことで、その両方を減らそうとしています。

**今回は、使う人をケアマネジャーに絞りました。** 道具そのものは、民生委員など聞き取りをする人なら使える作りです。絞った理由は2つです。内閣府の追補版（2025年6月）は、ケアマネジャーが普段の仕事の延長で計画づくりに関わる形を、入口の一つとして示しています。謝金を出して作成を頼む自治体もあります（鹿児島市は2026年8月から、1件3,000円）。頼まれたときに、増えた仕事の上へさらに重ならない形にしておくことが、この道具の役目です。

**まだ試してはいません。** 聞いたのは仕組みと困りごとで、この道具を現場で使ってもらった結果ではありません。当事者ご本人の声も、まだ聞けていません。

## どう使うか
見本の岡野ハルさん（架空の人物）では、22項目のうち14項目が聞かずに済み、話すのは8項目になります。

1. **2つのデータを入れる：** 使う人（ケアマネジャー、民生委員など）を選び、ケアプランの CSV と個別避難計画書の CSV を入れます。CSV なしでも始められます
2. **列をつなぐ：** 同じ意味の列をつなぎ、分かっていることは聞き直しません。2つのデータで値が違う列は黙って決めず、確かめる項目に残します
3. **話す：** 話のきっかけを1つずつ出します。最初の1問は、分かっている寝室を先に言って「もしものときに、心配なことはありますか？」から入ります。いきなり避難先を聞くと、身構えてしまうからです
4. **復唱して書き取る：** 聞いたことをご本人に確かめながら、ボタンか F2 キーを長押ししている間だけ復唱し、短く押すと送ります。聞き間違いは送る前に直せます。書き取り役が欄に割り振り、入った欄には色が付きます。違っていれば別の欄へ移せて、どの欄も手で直せます
5. **穴を見つける：** 点検役が計画の穴を見つけると、物差しを示して問いかけを出します。その問いかけでどの欄を埋めたいかを、耳打ちと同じ色で計画の欄に示します
6. **渡す：** 今日できたことと次の一歩をまとめます。埋まらなかった穴は隠さず、次の一歩に残します

渡す相手は3つで、同意は別々に取ります。

| 渡す相手 | 渡すもの | 決まり |
|---|---|---|
| ご本人 | 共有する紙 | 手伝う人が決まっていなくても渡せます。「大雨のときに、電話を1本もらえませんか」のような小さなお願いごとの案を選ぶと、ご本人がそのまま言える言い回しで載ります。頼むのはご本人かご家族で、道具は相手に連絡しません |
| 市 | 個別避難計画書の CSV | ご本人が同意した項目だけを出します。同意が1つでもあれば、ご本人を確かめる列（氏名、住所など）は一緒に出て、画面に列の名前を出します。同意が無ければ CSV は出ません |
| ケアプラン | 取り込んだものと同じ見出しの新しい CSV | 訪問で変わった内容を、市とは別の同意で書き出します。元のファイルは変えません。戻すのは見出しのある欄だけです |

## Claude の使い方
役目を3つに分け、[指示と答えの形](src/server/prompts.js)を1つのファイルにまとめています。

| 役目 | すること | 動くとき | 答えをどう確かめるか |
|---|---|---|---|
| 読み解き役 | CSV の列が計画のどの欄かを判断する。個別避難計画書の様式の見出しも読む | 取り込みのとき | 分からない列は「分からない」のまま人に聞く |
| 書き取り役 | 声メモを計画に書き込む | 声メモのたび | 根拠の文字がメモに無い書き込みは捨てる。答えを聞いていない問いかけは書き込まない。人が直した欄は上書きしない |
| 点検役 | 物差しに当たる穴と、問いかけや頼みごとの案を出す | 話の途中と訪問終了 | 物差しに無い指摘と医療の判断は捨てる |

考え方は3つです。

- **AI はご本人に話しかけません。** 聞き手のケアマネジャーに、次の問いかけを耳打ちするだけです。話すのも決めるのも人です
- **判断だけを Claude に頼みます。** 話のきっかけの順番、サービスの無い曜日、CSV の変換、「間に合うか」の足し算はプログラムがします。待たせず、結果がぶれないようにするためです
- **答えをそのまま信じません。** 答えは決まった形（JSON スキーマ）で受け取り、[プログラムが検査](src/server/claude.js)してから画面に出します。聞いていないこと、医療の判断、手伝いの約束に読める文は捨てます

モデルは3役とも Claude Opus 5.5 です。ご本人の暮らしに関わる判断なので、速さより読み違いの少なさを選びました。考える深さは役ごとに変えていて、毎回の声メモを待たせない書き取り役は浅め、読み解き役と点検役は中くらいです。

本物の Claude では、架空の人物の台本を通して確かめています（2026-11-03、通し2回で約0.85ドル）。

## Claude Code での作り方
コードはすべて Claude Code で書きました。任せきりにしないための仕組みを3つ置いています。

| 仕組み | すること | それで何ができたか |
|---|---|---|
| [レビュー役](.claude/agents/privacy-reviewer.md)（サブエージェント） | 書いた会話を見ていない、読み取り専用の別の目が、送る中身と出力を調べる | テストがすべて通ったあとに、声メモの生年月日が Claude に届く道筋を見つけた |
| [フック](.claude/settings.json) | 書き換えるたびにテストを流す。鍵の読み出し、公開への切り替え、履歴の上書きを止める。有料の実行は人に聞く | 壊したらその場で分かる。お金と公開の判断が人に戻る |
| Git のフック | コミットの前に、鍵と架空でない個人情報が混ざっていないかを調べる | テストに書いた実在しうる形の番号を止めた |

## 難しかったこと
守ることと、止めないことの両立です。

- テストがすべて通った時点で、レビュー役が、声メモの生年月日が Claude に届く道筋を見つけました。直して、破れ方をテストに残しました
- 塞ぐと今度は「公民館まで10-15分」を住所と判定して、訪問が止まりました。漏らさないことと話を止めないことは両方要るので、止めるのをやめて、置き換える形に作り直しました
- レビューと修正は8回繰り返しました。テストは294件、コミットは40件です（2026-11-06 時点）

## 守っていること
- AI はご本人に話しかけず、連絡もしません。決めるのは人です
- 医療の判断はしません
- デモのデータはすべて架空です。実在の個人情報は入れません
- 氏名・住所・電話番号・生年月日を Claude に送らないよう、ブラウザの中で記号や呼び名に置き換え、サーバーの入口でも形を調べます。送る中身は画面で見られます

機械には限界があります。

- **名前の見分け：** 入力していない人の名前は、「さん」が付かないときや平仮名のときに見分けられません。声メモでは「隣の人」「娘さん」のように続き柄で話してください
- **出す前の確認：** 手伝う人の同意がない間は、人の話が入った文を個別避難計画書から隠します。言葉の一覧には限りがあるので、出す内容は人が読んで確かめてください
- **声の入力：** パソコンの Chrome と Edge を前提にしていて、スマホでは確かめていません。声はブラウザの音声認識（Google）で処理されます。端末の中で処理する形への切り替えは今後の課題です

## 今できること、まだのこと
出口は個別避難計画書にしましたが、道具の作りは特定の様式に縛られていません。

| できること | 今の状態 |
|---|---|
| **どの様式も読める：** 見出しのある CSV なら、読み解き役が見出しを読み、計画の欄につなぎます。合わない列は話の中で聞く欄として足します | 動きます（Excel や PDF は直接読めません。公開版に入れるのは架空のデータだけです） |
| **様式を切り替える：** 同じ聞き取りの内容を、別の様式の形で出します | 動きます（ハッカ村とミント市、手元の CSV。どちらの村と市も架空です） |
| **データを戻す：** 話で変わった欄を、ご本人の同意があれば、取り込んだケアプランと同じ見出しの CSV に戻します | 動きます（介護ソフトへの実際の取り込みは未確認です） |
| **テンプレートを3つ以上入れて、それぞれの形で出す** | 未実装です。今は入口と出口の2つで、同じ仕組みで増やせる設計です |
| **各テンプレートへデータを戻し、更新し続ける** | 未実装です |

確かめていないことは次のとおりです。

- 実際の介護ソフトが、アセスメントの項目を CSV で出せるか
- 実在の様式と、市のソフトへの実際の取り込み（CSV で取り込めるとは聞いています）
- 当事者ご本人の声と、現場で使ってもらった結果

実際に使うには、様式ごとに誰へ何を渡してよいかの同意の整理、人による確認の手順、市の決まりの確認が必要です。

## 動かし方
Node.js 22 以上で動きます。

```bash
node server.mjs
```

`http://localhost:5177` を開きます。鍵が無いと、台本の言葉にだけ反応する**仮の答え**で動き、画面にもそう出ます。

本物の Claude につなぐときは、部品を入れて `.env` に鍵を書きます（`.env.example` を参照）。

```bash
npm ci
```

```bash
node --env-file=.env server.mjs
```

鍵があるのに Claude が失敗したときは、仮の答えに逃げず、失敗と画面に出します。

## 確かめ方
```bash
npm test
```

本物の Claude を呼ばずに、送る中身、答えの受け取り方、外に置くときの決まりを調べます。

架空の人物の台本を本物の Claude に通し、出るべき指摘と出てはいけない指摘、かかった費用を確かめるには、次のコマンドを使います（有料です）。

```bash
node --env-file=.env scripts/try-claude.mjs --go
```

## 外に置くとき
`HOST=0.0.0.0` と、12文字以上の `APP_PASSWORD` が必要です。無いと起動しません。`PUBLIC_DEMO=1` では、CSV は入れられますが、架空のデータだけを入れるよう画面で伝え、続きから再開と手入力の入口を隠します。入れた値はブラウザの中だけで、サーバーは見出しと記号だけを受け取ります。回数の上限は `LIMIT_PER_MINUTE`（既定40）、`LIMIT_PER_DAY`（既定500）、`LIMIT_PER_CLIENT_DAY`（接続元ごと、既定200）です。
