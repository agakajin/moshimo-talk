# hinan-hanashi（仮の名前）

個別避難計画づくりを支える道具。**同じことを二度聞かない。空いた時間で、もしもの話をする。**

ケアマネジャーが訪問して、話しながら個別避難計画と本人に渡す1枚を作れます。何度も同じことを聞かれる利用者さんと、聞いて書き直す支援者の負担を減らし、話す時間を作ります。

Built with Claude: Japan 2026 の期間中（2026-11-02〜）に開発しています。

## なぜ作ったか
個別避難計画は、災害のとき一人で避難するのが難しい人について、誰と、何で、どこへ、何分で避難するかを前もって決めておく計画です。奄美市の名瀬地区では、2025年6月の市議会答弁で作成済みが約1割でした（奄美市全体は 2026-04-01 時点で 30.6%）。

最初は入力ツールを作るつもりでした。考えが変わったきっかけは2つです。

- **書く前の段階：** 国の調査（2026-04-01）を集計すると、計画がない約568万人のうち同意済みは約23万人（4%）で、約546万人は同意の手前にいます。内訳は分かりません。内閣府の「個別避難計画に取り組むみなさまへ」追補版（2025年6月）は、計画づくりが地域のつながりの再構築につながるとしています。足りないのは入力より、話すことかもしれないと考えました
- **情報はもうある：** 個別避難計画で使いたい情報は、ケアプランのアセスメント、避難行動要支援者名簿、救急医療情報キットなどに、様式を変えて入っています。それでも、計画を作るときに利用者さんは同じことを答えています

そこで、2つのデータをつなぎ、分かっていることは聞かず、必要なことだけを話す道具に変えました。当事者の声はまだ聞けていないので、これらは仮説です。

## 何をする道具か
1. **2つのデータを入れる：** 使う人（ケアマネジャー、民生委員など）を選び、ケアプランの CSV と個別避難計画書の CSV を入れます。ドラッグかファイル選択で入れられ、CSV なしでも始められます
2. **列をつなぐ：** 同じ意味の列をつなぎ、分かっていることは聞き直しません。2つのデータで値が違う列は黙って決めず、確かめる項目に残します
3. **話す：** 話のきっかけを1つずつ出します。最初の1問は寝室を先に言って「もしものときに、心配なことはありますか？」から入ります。いきなり避難先を聞くと身構えてしまうからです。2問目からは違っていた値を確かめ、様式の必須の欄につながる話を先に聞きます
4. **声メモ：** 聞いたことをご本人に確かめながら、ボタンか F2 キーを長押ししている間だけ復唱し、短く押すと送ります。キーは変更できます。聞き間違いは送る前に直せます（「要介護に」→「要介護2」）
5. **欄に入る：** 書き取り役が欄に割り振り、入った欄には色が付きます。違っていれば「移す」で別の欄へ移せて、どの欄も手で直せます。**欄に入らなかった声メモは、計画の欄へドラッグするか「欄へ入れる」で人が入れます**
6. **穴を見つける：** 点検役が計画の穴を見つけると、物差しを示して問いかけを割り込ませます。問いかけは話のきっかけより優先します
7. **訪問終了：** 今日できたことと次の一歩をまとめ、埋まらなかった穴は隠さず次の一歩に残します。渡す相手ごとに3つのタブがあります
   - **ご本人へ：** 本人の1枚。手伝う人が決まっていなくても渡せます。「ご近所に頼めそうなこと」の案（「大雨のときに、電話を1本もらえませんか」など）を選ぶと、ご本人がそのまま言える言い回しで1枚に載ります。頼むのはご本人かご家族で、道具は相手に連絡しません。頼めたかどうかは人が印を付けます
   - **市へ：** 本人が同意した項目だけ、個別避難計画書の CSV に出します（同意が1つでもあれば、本人を確かめる列〔氏名、住所など〕は一緒に出ます。画面に列の名前を出します）。同意が無ければ CSV は出ず、渡さないと決めても1枚は渡せます
   - **ケアプランへ：** 訪問で変わった内容を、取り込んだケアプランと同じ見出しの新しい CSV に、市へ渡すのとは別の同意で書き出せます。元のファイルは変えません。戻すのは見出しのある欄だけで、見出しの無い内容（心配な災害や避難場所など）は保存しません。変わる所は保存の前に画面で見られます

個別避難計画書の様式とケアプランの CSV の見出しを読み、聞く欄を合わせて作ります。計画に無い列は、話の中で聞く欄として足します。個別避難計画書の見本はハッカ村とミント市（どちらも架空）で、様式を増やせる作りです。ケアプラン用の CSV を介護ソフトへ実際に取り込めるかは、ソフトの対応しだいです。実際の介護ソフトがアセスメントの項目を CSV で出せるかも未確認です。

## 個別避難計画書は最初の一歩
今回は同じことを何度も聞かれるペインを解消するため、個別避難計画書を出口にしました。ただ、道具の作りは特定の様式に縛られていません。

| できること | 今の状態 |
|---|---|
| **どの様式も読める：** 見出しのある CSV なら、読み解き役が見出しを読み、計画の欄につなぎます。合わない列は話の中で聞く欄として足します | 動きます（Excel や PDF は直接読めません。公開デモは架空の見本だけです） |
| **様式を切り替える：** 同じ聞き取りの内容を、別の様式の形で出します | 動きます（ハッカ村とミント市、手元の CSV） |
| **データを戻す：** 話で変わった欄を、本人の同意があれば、取り込んだケアプランと同じ見出しの CSV に戻します（見出しのある欄だけ） | 動きます（介護ソフトへの実際の取り込みは未確認です） |
| **テンプレートを3つ以上入れて、それぞれの形で出す** | 今は入口と出口の2つです。同じ仕組みで増やせる設計で、技術的には可能です（未実装） |
| **各テンプレートへデータを戻し、更新し続ける** | ケアプランへ戻す仕組みを広げれば、技術的には可能です（未実装） |

実際に使うには、様式ごとに誰へ何を渡してよいかの同意の整理と、市の決まりの確認が必要です。

## 守っていること
- AI は高齢者に話しかけず、連絡もしません。決めるのは人です
- 医療の判断はしません
- デモのデータはすべて架空です。実在の個人情報は入れません
- 氏名・住所・電話番号・生年月日を Claude に送らないよう、ブラウザの中で記号や呼び名に置き換え、サーバーの入口でも形を調べます。送る中身は画面で見られます
- ただし、機械には限界があります。入力していない人の名前は、「さん」が付かないときや平仮名のときに見分けられません。声メモでは「隣の人」「娘さん」のように続き柄で話してください。手伝う人の同意がない間は人の話が入った文を個別避難計画書から隠しますが、言葉の一覧には限りがあるので、出す内容を人が読んで確かめてください。声の入力はパソコンの Chrome と Edge を前提にしていて、スマホでは確かめていません。声はブラウザの音声認識（Google）で処理されます。端末の中で処理する形への切り替えは今後の課題です。実際の運用の前に、人による確認と市の決まりの確認が必要です

## Claude の使い方
役目を3つに分け、[指示と答えの形](src/server/prompts.js)を1つのファイルにまとめています。

| 役目 | すること | 動くとき | 答えをどう確かめるか |
|---|---|---|---|
| 読み解き役 | CSV の列が計画のどの欄かを判断する。個別避難計画書の様式の見出しも読む | 取り込みのとき | 分からない列は「分からない」のまま人に聞く |
| 書き取り役 | 声メモを計画に書き込む | 声メモのたび | 根拠の文字がメモに無い書き込みは捨てる。答えを聞いていない問いかけは書き込まない。人が直した欄は上書きしない |
| 点検役 | 物差しに当たる穴と、問いかけや頼みごとの案を出す | 話の途中と訪問終了 | 物差しに無い指摘と医療の判断は捨てる |

話のきっかけの順番、サービスの無い曜日、CSV の変換、「間に合うか」の足し算はプログラムがします。AI を待たせず、結果がぶれないようにするためです。

## 難しかったこと
守ることと、止めないことの両立です。

- テストがすべて通った時点で、会話を見ていないレビュー役が、声メモの生年月日が Claude に届く道筋を見つけました。直して、破れ方をテストに残しました
- 塞ぐと今度は「公民館まで10-15分」を住所と判定して、訪問が止まりました。漏らさないことと話を止めないことは両方要るので、止めるのをやめて、置き換える形に作り直しました
- レビューと修正は8回繰り返しました

## 動かし方
Node.js 22 以上で動きます。

```bash
node server.mjs
```

`http://localhost:5177` を開きます。鍵が無いと、台本の言葉にだけ反応する**仮の答え**で動き、画面にもそう出ます。

本物の Claude につなぐときは、部品を入れて `.env` に鍵を書きます（`.env.example` を参照）。

```bash
npm ci
```

```bash
node --env-file=.env server.mjs
```

鍵があるのに Claude が失敗したときは、仮の答えに逃げず、失敗と画面に出します。

## 確かめ方
```bash
npm test
```

本物の Claude を呼ばずに、送る中身、答えの受け取り方、外に置くときの決まりを調べます。

架空の人物の台本を本物の Claude に通し、出るべき指摘と出てはいけない指摘、かかった費用を確かめるには、次のコマンドを使います（有料です）。

```bash
node --env-file=.env scripts/try-claude.mjs --go
```

## 外に置くとき
`HOST=0.0.0.0` と、12文字以上の `APP_PASSWORD` が必要です。無いと起動しません。`PUBLIC_DEMO=1` で架空のサンプルだけになります。公開デモのサーバーは、架空のサンプル以外の列を読みません。回数の上限は `LIMIT_PER_MINUTE`（既定40）、`LIMIT_PER_DAY`（既定500）、`LIMIT_PER_CLIENT_DAY`（接続元ごと、既定200）です。

## Claude Code での作り方
- [フック](.claude/settings.json)：書き換えるたびにテストを流す。鍵の読み出し、公開への切り替え、履歴の上書きを止める。有料の実行は人に聞く
- [レビュー役](.claude/agents/privacy-reviewer.md)：書いた会話を見ていない読み取り専用のサブエージェントが、送る中身と出力を調べる
- Git のフック：コミットの前に、鍵と架空でない個人情報が混ざっていないかを調べる
